Local Neural Inference & Dual-Pathway Retrieval

Dense Semantic Retrieval & Hybrid Search (Phase 7)

Unifies exact keyword precision with continuous vector representations using local ONNX Runtime transformer inference (all-MiniLM-L6-v2), authentic 30,522-token WordPiece tokenization, dynamic sequence tensor sizing, and Reciprocal Rank Fusion (RRF).

Dual-Pathway Hybrid Architecture

Incoming queries are routed simultaneously through the BM25 Lexical Engine and the Dense Semantic Engine. The resulting rank lists are blended using scale-invariant Reciprocal Rank Fusion without fragile score tuning.

PATH A

BM25 Lexical Retrieval

Inverted index postings traversal, Robertson-Spärck Jones IDF, and sublinear term saturation. Dominates exact keyword matches, technical IDs (e.g. RFC 9309), and adjacent positional phrases.

PATH B

Dense Semantic Retrieval

Pure Java WordPiece tokenizer + ONNX Runtime all-MiniLM-L6-v2 CPU execution. Projects queries and documents into 384-D latent space with L2 unit normalization, solving vocabulary mismatch.

FUSION

Reciprocal Rank Fusion (RRF)

Combines rank positions via RRF(d) = Σ 1 / (60 + r_m(d)). Completely immune to scale drift between unbounded BM25 scores and [-1, 1] cosine similarities.

Data Integrity & Self-Healing Architecture

Index Lifecycle, Consistency & Recovery (Phase 8)

Guarantees that documents never exist in an inconsistent state across relational storage, lexical indexes, positional postings, corpus statistics, and ONNX dense embeddings.

The 10-State Document Lifecycle State Machine

Documents strictly transition through validated lifecycle states. Only documents in ACTIVE status are searchable. Documents in DELETING, FAILED, or PROCESSING are completely isolated from query evaluation.

DISCOVERED → FETCHED → PROCESSING → INDEXING → EMBEDDING → ACTIVE (Searchable)

Staged Two-Phase Transactions

Stage 1 computes WordPiece tokenization and ONNX transformer inference outside database transactions (0 locks held). Stage 2 atomically commits version increments, postings, and vectors. Stage 3 syncs memory.

Non-Destructive Reconciliation

IndexIntegrityChecker audits across relational tables, in-memory indexes, corpus stats, and vector storage to detect orphaned postings, missing documents, and drifted metrics.

Automated Self-Healing Repair

IndexRepairService runs in DRY_RUN or REPAIR mode, automatically reconstructing missing postings, purging orphaned vectors, and resynchronizing memory to 100% health.

Local Execution

Quickstart Guide

Launch the search engine locally in under 60 seconds.

Option A: Zero-Docker Instant Dev Runner (Recommended)

Uses an in-memory PostgreSQL-compatible H2 database with 24 multi-domain encyclopedia documents auto-seeded on startup.

cd backend
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=dev"

Option B: Full-Stack Web App (Backend + React Frontend)

Launch both the Java 21 Spring Boot search engine and the interactive Vite 6 React SERP UI.

# Terminal 1: Backend (Port 8080)
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=dev"

# Terminal 2: Frontend (Port 5173)
cd frontend
npm run dev

Option C: Persistent PostgreSQL 16 Docker Mode

# 1. Start PostgreSQL 16 Container
docker compose up -d

# 2. Run backend
cd backend
.\mvnw.cmd spring-boot:run

Option D: Run All 497 Automated Tests (484 Backend + 13 Frontend)

# Run 484 Backend Tests
cd backend
.\mvnw.cmd test

# Run 13 Frontend Tests
cd ../frontend
npm test
